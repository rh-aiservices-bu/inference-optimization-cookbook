qwen35-9b-fp8, qwen3_next_mtp method · 128 input (prompt) tokens, 256 output tokens per request · Overview compares every config at every concurrency level; each config's own tab shows its full concurrency curve per metric, overlaid against baseline.

Pros

  • Lower inter-token latency (ITL) and time-per-output-token (TPOT) at every concurrency level tested — best with 2-4 draft tokens
  • Higher output throughput, especially at low-to-moderate concurrency

Cons

  • Slightly worse time-to-first-token (TTFT) at low concurrency — fixed per-step draft overhead is paid even on the first token
  • Draft acceptance rate falls as token count rises, so the benefit shrinks (and can reverse) past about 4-5 draft tokens
  • Requires more GPU memory to load: 13.18 GiB vs 12.73 GiB for baseline (~0.45 GiB fixed overhead for the draft model, regardless of token count)
